1. Purpose

This plan lets an independent tester verify the GoldenGlow website end to end using only the website — no server, database or Supabase access is required.

You will test three roles:

  1. Worker — create a profile, save jobs, apply with a CV, track applications.
  2. Employer — manage a company profile, post and edit jobs, review applications.
  3. Admin — review accounts and jobs, approve/reject postings, manage applications, enquiries and saved searches.

Every test case has an ID, steps, the expected result and a result box. Record Pass / Fail / Blocked and attach a screenshot or short recording for every failure.

Important: This is the live production site. Only create data prefixed with QA- and only delete records you created yourself. Never upload a real passport, Iqama, CV or any real personal document. Use a dummy PDF for CV tests.

2. Accounts and access

All three roles sign in through the same page: https://goldenglowqr.com/login There is no separate admin URL or admin password. The admin account is a normal account whose profile has been given the admin role by GoldenGlow.

2.1 Credentials

GoldenGlow will fill in the admin row before hand-off. For worker and employer you can either use accounts supplied by GoldenGlow or register your own (see 2.2).

Role Email Password Notes
Worker ______________________________ ____________________ Supplied, or self-register
Employer ______________________________ ____________________ Supplied, or self-register
Admin ______________________________ ____________________ Supplied separately by GoldenGlow

The admin account is for admin tests only. Do not use it for the worker or employer cases — use separate worker and employer accounts, otherwise their dashboards will not contain the test data you expect.

Never share these credentials or change the admin password.

2.2 Registering your own worker / employer accounts

If GoldenGlow only supplied the admin account:

  1. Use your own email with a plus-address, for example:
    • yourname+gg-worker@gmail.com
    • yourname+gg-employer@gmail.com
  2. Go to /signup and pick Worker or Employer.
  3. Fill in the form and submit.
  4. If a “Check your inbox” screen appears, open the confirmation email (sender info@goldenglowqr.com) and click the link. Check spam if it is not there within a few minutes.
  5. Sign in at /login.

Confirmation emails are rate-limited. Do not re-submit more than two or three times; if you see “Too many attempts”, wait and use an account that is already confirmed.

2.3 Using three roles at once

Use three different browsers or three separate browser profiles, for example Chrome, Edge and Firefox. Multiple incognito windows in the same browser can share a session.

Window Signed in as
Window 1 Worker
Window 2 Employer
Window 3 Admin

3. Before you start

  • Use a current version of Chrome, Edge, Firefox or Safari.
  • Set up the three windows described in 2.3.
  • Have a dummy PDF ready (under 5 MB) to use as a CV. It must not contain real personal data.
  • Use test data only, for example QA – Electrician, QA – Test Employer Ltd, qa-worker@…, qa-employer@….
  • Allow pop-ups for goldenglowqr.com (the admin CV link opens in a new tab).
  • Optional: open the browser developer console (F12) so you can note any red errors.
  • Take a screenshot for every failed or blocked test.
  • Do not change or delete data you did not create.
  • Do not use the site with real candidate or worker documents.

3.1 Site behaviour you should expect (not bugs)

  • The vacancies currently on the site may include demo data, which shows a “Sample listing” badge. Jobs created by an employer become public only after an admin verifies them, and then show “Verified”. Your job counts may differ from the examples in this document.
  • The jobs page shows 6 jobs initially; Load More reveals the rest.
  • Confirmation and contact emails are sent from info@goldenglowqr.com. They may take a minute and can land in spam on the first send.
  • Status changes made by another role may require a page reload to appear instantly.
  • A CV link in the admin panel is a short-lived signed link; if it expires, click the CV filename again.
  • The contact form may say the enquiry was saved but email delivery is not switched on. Record it as an observation; the enquiry should still appear in the admin panel.

4. How to record results

For every case mark one of:

  • Pass — behaves exactly as described.
  • Fail — differs from the expected result. Attach a screenshot and note the browser.
  • Blocked — cannot be completed (say why, e.g. no confirmation email received).

Use this bug format for every failure:

Bug ID:
Title:
Role:            Worker / Employer / Admin / Public
Page URL:
Browser / OS:
Steps to reproduce:
1.
2.
3.
Expected result:
Actual result:
Severity:        Critical / High / Medium / Low
Evidence:        screenshot / recording / console error
Was this data created by you?   Yes / No

Severity guide:

  • Critical — cannot sign in, cannot apply, data lost, another role’s data visible.
  • High — a main task fails (post job, verify job, open CV, update status).
  • Medium — validation, copy, layout or persistence problem with a workaround.
  • Low — cosmetic or minor wording issue.
